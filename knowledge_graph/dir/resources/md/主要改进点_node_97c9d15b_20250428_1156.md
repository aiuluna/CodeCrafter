# 主要改进点

## 将antd-renderer的多文件支持适配到aries-ui-renderer

### 1. 实现虚拟文件系统

#### 虚拟文件系统接口设计
```typescript
interface VirtualFileSystem {
  // 存储文件内容
  files: Record<string, string>;
  
  // 添加文件到虚拟文件系统
  addFile(path: string, content: string): void;
  
  // 根据路径获取文件内容
  getFile(path: string): string | null;
  
  // 判断文件是否存在
  fileExists(path: string): boolean;
  
  // 解析相对路径，转换为规范化路径
  resolvePath(currentPath: string, relativePath: string): string;
  
  // 清空所有文件
  clear(): void;
}
```

#### 实现和优势
- 提供统一的文件访问接口
- 支持路径解析和规范化
- 方便扩展和维护
- 解耦文件存储和处理逻辑

### 2. 增强组件创建逻辑

#### 递归处理组件依赖
```typescript
function processFile(filename: string, vfs: VirtualFileSystem): any {
  // 检查模块缓存
  if (modules[filename]) {
    return modules[filename].exports;
  }
  
  // 从虚拟文件系统获取文件
  const content = vfs.getFile(filename);
  if (!content) {
    throw new Error(`找不到文件: ${filename}`);
  }
  
  // 解析组件，处理依赖
  const component = parseComponent(content, filename, vfs);
  
  // 缓存处理结果
  modules[filename] = { exports: component };
  
  return component;
}
```

#### 优势
- 支持组件之间的依赖关系
- 避免循环依赖问题
- 提高渲染性能
- 处理复杂的组件树

### 3. 修改文件处理方式

#### Vue SFC解析适配
```typescript
function parseComponent(content: string, filename: string, vfs: VirtualFileSystem) {
  // 检查是否是.vue文件
  if (filename.endsWith('.vue')) {
    // 使用现有的Vue SFC解析逻辑
    return parseSFC(content, filename, vfs);
  } else {
    // 处理.js/.ts文件
    return parseScript(content, filename, vfs);
  }
}
```

#### 保持兼容性
- 兼容现有的单文件组件格式
- 支持.js/.ts等不同类型文件
- 适配Vue特有的组件结构
