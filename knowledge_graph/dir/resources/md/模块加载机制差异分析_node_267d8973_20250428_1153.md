# 模块加载机制差异

## antd-renderer 模块加载机制

1. **转换与执行**:
   - 使用 `@babel/standalone` 转换 TypeScript/JSX 代码为可执行的 JavaScript
   - 通过 `new Function()` 动态执行转换后的代码
   - 模拟 CommonJS 模块系统，提供 `require`, `module`, `exports` 参数

2. **递归处理依赖**:
   - 使用 `processFile` 函数递归处理文件依赖关系
   - 先检查模块缓存，避免重复处理
   - 支持相对路径导入解析

3. **模块缓存机制**:
   - 使用 `modules` 对象缓存已处理的模块
   - 有效避免循环依赖问题
   - 提高渲染性能

4. **导入处理**:
   - 明确区分外部依赖库导入和内部文件导入
   - 对外部库提供详细的错误提示和组件建议
   - 自动处理各种扩展名

## aries-ui-renderer 模块加载机制

1. **简单解析方式**:
   - 使用正则表达式匹配 Vue 组件的标签（`<template>`, `<script>`, `<style>`）
   - 通过正则表达式提取导入语句，不支持复杂的导入形式

2. **限制的模块加载**:
   - 只处理单个文件，无法处理跨文件引用
   - 通过 `new Function()` 执行组件脚本，但没有提供模块环境

3. **预定义模块**:
   - 仅支持从 `mockModules` 中加载预定义模块（Vue, Aries UI, 图标库等）
   - 无法动态加载或解析其他模块

4. **无模块缓存**:
   - 没有实现模块缓存机制
   - 每次渲染都重新处理整个组件

## 关键差异总结

| 特性 | antd-renderer | aries-ui-renderer |
|------|--------------|-------------------|
| 代码转换 | 使用 Babel 转换 | 使用正则表达式提取 |
| 依赖处理 | 递归处理所有依赖 | 不支持多文件依赖 |
| 模块缓存 | 有完整缓存机制 | 无缓存机制 |
| 导入支持 | 支持相对路径和库导入 | 仅支持库导入 |
| 错误提示 | 详细的错误信息 | 基本错误信息 |

## 改进建议

1. 为 aries-ui-renderer 添加递归处理依赖的能力
2. 实现模块缓存机制，避免重复处理
3. 增强导入解析逻辑，支持相对路径
4. 改进错误处理，提供更详细的错误信息
