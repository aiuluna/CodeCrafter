# 路径解析实现差异

## antd-renderer 路径解析实现

1. **完整的路径处理**:
   - 使用 `path-browserify` 库提供类似 Node.js 路径 API 的功能
   - 支持路径拼接、解析和规范化

2. **路径解析逻辑**:
   - 完整支持相对路径解析（`./`, `../`）
   - 实现了目录拼接和文件名解析
   - 处理路径中的特殊符号和冗余部分

3. **扩展名处理**:
   - 自动尝试多种扩展名（.ts, .tsx, /index.ts, /index.tsx）
   - 实现了类似 Node.js 模块解析的策略
   - 兼容各种导入形式

4. **路径查找算法**:
   ```javascript
   const resolvedPath = importPath.startsWith(".")
     ? path.join(path.dirname(filename), importPath).replace(/^\//, "")
     : importPath;

   const possiblePaths = [
     resolvedPath,
     resolvedPath + ".ts",
     resolvedPath + ".tsx",
     resolvedPath + "/index.ts",
     resolvedPath + "/index.tsx",
     resolvedPath.replace(/\.(ts|tsx)$/, ""),
   ];

   const normalizedPath = Object.keys(files).find(file =>
     possiblePaths.includes(file),
   );
   ```

## aries-ui-renderer 路径解析实现

1. **缺少路径处理**:
   - 没有实现任何路径解析逻辑
   - 不支持相对路径导入处理

2. **仅处理模块名**:
   - 仅提取 `import` 语句中的模块名称
   - 不处理相对路径或路径解析

3. **导入处理限制**:
   ```javascript
   scriptContent = scriptContent.replace(
     /import\s+(\{[^}]+\}|\w+)\s+from\s+['"]([^'"]+)['"]/g,
     (match, importNames, moduleName) => {
       imports[moduleName] = importNames
         .replace(/[{}]/g, "")
         .split(",")
         .map((name: string) => name.trim())
       return ""
     },
   )
   ```
   - 上述代码只能提取模块名，没有路径处理逻辑

## 关键差异总结

| 特性 | antd-renderer | aries-ui-renderer |
|------|--------------|-------------------|
| 路径库支持 | 使用 path-browserify | 无路径处理库 |
| 相对路径解析 | 完整支持 | 不支持 |
| 扩展名处理 | 自动尝试多种扩展名 | 无扩展名处理 |
| 路径规范化 | 支持路径规范化 | 无路径规范化 |

## 改进建议

1. 引入 `path-browserify` 库处理路径解析
2. 实现相对路径解析逻辑，支持 `.` 和 `..` 
3. 添加扩展名自动匹配功能，针对 `.vue`, `.js`, `.ts` 等多种扩展名
4. 实现路径规范化函数，处理路径中的冗余部分
