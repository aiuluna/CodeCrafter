# 组件渲染流程差异

## antd-renderer 组件渲染流程

1. **完整渲染流程**:
   - 接收多个文件内容和入口文件路径
   - 从入口文件开始递归处理所有依赖
   - 生成完整的组件树并渲染

2. **代码处理与执行**:
   - 使用 @babel/standalone 处理 TypeScript/JSX 代码
   - 通过模拟的 CommonJS 环境执行代码
   - 支持复杂的模块间依赖关系

3. **错误处理机制**:
   - 利用 React 的 ErrorBoundary 捕获渲染错误
   - 提供详细的错误信息和建议
   - 专门的错误展示组件

4. **组件生命周期**:
   ```javascript
   const parseComponents = async () => {
     try {
       setError(null);
       processFile(entryFile);
       const exportedComponent = modules[entryFile].exports.default;
       if (!exportedComponent) {
         // 错误处理
         return;
       }
       setComponent(() => exportedComponent);
       onSuccess();
     } catch (error) {
       // 错误处理
     }
   };
   ```

## aries-ui-renderer 组件渲染流程

1. **简化渲染流程**:
   - 接收单个字符串文件
   - 使用正则表达式提取模板、脚本和样式
   - 直接创建 Vue 组件并渲染

3. **错误处理**:

   - 展示基本错误信息
   - 没有细致的错误定位

## 关键差异总结

| 特性 | antd-renderer | aries-ui-renderer |
|------|--------------|-------------------|
| 文件处理 | 支持多文件递归处理 | 仅支持单个字符串处理 |
| 组件创建 | 通过模块系统构建 | 通过正则提取和直接创建 |
| 错误处理 | 完整的错误边界和提示 | 基本错误捕获 |
| 代码转换 | 使用 Babel 转换 | 不使用代码转换工具 |

## 改进建议

1. 修改 aries-ui-renderer 的组件创建逻辑，支持多文件递归处理
2. 增强错误处理机制，提供更详细的错误信息
3. 实现文件依赖分析和处理
4. 保留 Vue 单文件组件的处理逻辑，但增加对多文件依赖的支持
